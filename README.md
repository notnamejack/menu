# Osteria Alba — цифровое меню

Статический сайт меню для зала: планшет, телефон и телевизор. Данные лежат в одном JSON, фото и видео — рядом. Админка коммитит правки в репозиторий, GitHub Actions выкладывает сайт на GitHub Pages. Своей базы и сервера нет.

Заведение в сиде: **Osteria Alba**, подзаголовок cucina italiana. Светлая тема: тёплый серый фон, белые карточки, тонкий сериф в шапке. Цены в рублях.

## 1. Локальный запуск

```bash
npm install
npm run dev
```

Откроется `http://localhost:5173/`. Сборка: `npm run build`, превью сборки: `npm run preview`.

Локально `base` в Vite равен `/`. На Pages он становится `/<имя-репозитория>/`, потому что workflow передаёт `BASE_PATH`.

## 2. Репозиторий и GitHub Pages

1. Создайте репозиторий и запушьте ветку `main`.
2. Settings → Pages → Source: **GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` запускается на push в `main` и вручную (`workflow_dispatch`).
4. После зелёного прогона сайт доступен по адресу `https://<owner>.github.io/<repo>/`.

Первый деплой иногда просит подтвердить environment `github-pages` в настройках репозитория.

## 3. Токен для админки

Fine-grained personal access token:

1. GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens.
2. Repository access: **только этот репозиторий**.
3. Permissions → Repository → **Contents: Read and write**.
4. Для простого сохранения в `main` этого достаточно. Pull requests не нужны: editorial workflow выключен, коммит идёт сразу в `main`.

В `public/admin/config.yml` замените плейсхолдер:

```yaml
backend:
  name: github
  repo: OWNER/REPO   # например octocat/osteria-alba-menu
  branch: main
```

`OWNER/REPO` — владелец и имя репозитория на GitHub. Без этой замены вход в админку не найдёт репозиторий.

## 4. Вход в админку

Админка — отдельная страница, не маршрут гостевого SPA:

- локально: `http://localhost:5173/admin/`
- на Pages: `https://<owner>.github.io/<repo>/admin/`

На экране входа Sveltia CMS нажмите **Sign in with token** / **Войти с токеном** (подпись зависит от языка браузера) и вставьте PAT. Кнопку GitHub через Netlify можно не использовать: свой OAuth не настроен, `base_url` в конфиге нет, поэтому вход по токену штатный.

Токен хранит сам Sveltia в `localStorage` браузера. В репозиторий он не попадает.

Интерфейс CMS на русском, если язык браузера русский. Отдельный ключ `locale` Sveltia игнорирует, поэтому в конфиге его нет.

## 5. Сменить цену и добавить блюдо с видео

1. Войдите в админку и откройте коллекцию **Меню** (файл `public/data/menu.json`).
2. Раскройте список **Блюда**, найдите карточку и измените поле **Цена** (целое число рублей).
3. Стоп-лист: выключите **В наличии**. Гость увидит серую карточку «Нет в наличии». В JSON это `available: false`.
4. Скрыть блюдо совсем: выключите **Опубликовано** (`published: false`).
5. Новое блюдо: **Add** / **Добавить** в списке блюд. Заполните ID латиницей (`new-pasta`), категорию, название, описание, состав, цену, вес, калории, теги, порядок.
6. В поле **Фото** загрузите WebP или JPG. В поле **Видео** — MP4. Сохраните.
7. Sveltia коммитит `public/data/menu.json` и новые файлы в `public/media/`.

Пути в сиде без ведущего слэша: `media/carbonara.webp`. При сохранении Sveltia может записать `/media/...` — гостевой сайт снимает ведущий слэш в `assetUrl`.

## 6. Видео одной командой ffmpeg

720p, без звука, не длиннее 10 секунд. Если файл больше 5 МБ, поднимите `-crf` (например до 33) или укоротите `-t`.

```bash
ffmpeg -y -i input.mp4 -t 10 -an -vf "scale=-2:720" -c:v libx264 -profile:v main -pix_fmt yuv420p -crf 30 -movflags +faststart out.mp4
```

Короткий наезд на фото того же блюда (5 секунд, 720p, без звука):

```bash
ffmpeg -y -i photo.webp -vf "scale=1800:-2,zoompan=z='min(zoom+0.0012,1.12)':x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)':d=125:s=1280x720:fps=25" -an -c:v libx264 -profile:v main -pix_fmt yuv420p -crf 32 -movflags +faststart out.mp4
```

В сиде у четырёх блюд такие ролики: капрезе, пенне аль рагу, лосось на гриле, тирамису. Так ролик совпадает с карточкой.

## 7. Киоск на планшете

- iPad: включите **Guided Access** (Настройки → Универсальный доступ) и откройте меню в Safari или в режиме «На экран Домой».
- Android: **Fully Kiosk Browser**, стартовый URL с `?kiosk=1`.
- Пример: `https://<owner>.github.io/<repo>/?kiosk=1`

Режим запоминается в `sessionStorage`. Кнопка «Киоск» делает то же самое. В киоске скрыта ссылка «Для кухни», зоны нажатия от 48px, выделение текста отключено, мелкие подписи не меньше 16px. После 60 секунд без касаний, клавиш и прокрутки закрывается карточка, очищается поиск, страница уезжает наверх, категория сбрасывается на «Всё меню».

Выход: кнопка «Закрыть киоск» или адрес с `?kiosk=0`.

## 8. Демо на две минуты

Честно про деплой: Actions после коммита обычно занимает около минуты. Пока прогон не зелёный, второй экран старое меню не увидит. На встрече показывайте локальный `npm run dev` или заранее сохранённую версию. Второй планшет обновите после зелёного workflow.

1. Гостевое меню на планшете в альбоме: категории слева капсом, белые карточки справа. Тальята серая («Нет в наличии»). Брускетты нет — она не опубликована.
2. Откройте «Пенне аль рагу», покажите видео, состав и строку `320 г | 890 ₽`. Закройте по крестику, по оверлею или Escape.
3. В поиске наберите «тальята» — останется стоп-лист. Очистите поиск. «Брускетта» ничего не находит.
4. Админка → Меню → карбонара: цена `890`. У тальяты включите «В наличии» или, наоборот, выключите «В наличии» у лосося. Сохраните.
5. Скажите, что кухня уже нажала «сохранить», а зал увидит это после деплоя. Пока Actions жёлтый — листайте локальное превью.
6. Когда workflow зелёный, на втором устройстве обновите страницу гостевого меню. Запрос к `menu.json` идёт с `?t=время`, кэш не держит старый файл.

## 9. Что выбрано в этой сборке

- Имя: **Osteria Alba**, подзаголовок «cucina italiana». Это меню зала, не сайт-визитка: без брони стола и без адреса.
- Стиль: фон `#e7e5e1`, белые карточки, вордмарк Cormorant Garamond капсом с широким трекингом, текст Manrope. Тёмный синий только как тонкий акцент. Сетка: телефон — 1 колонка, планшет в альбоме — 2, широкий экран — 3.
- Стек: Vite, React, TypeScript, Tailwind, иконки `lucide-react`, анимации только CSS. Роутера нет: гость — одна страница, админка — `public/admin/`.
- `base`: локально `/`, на Pages `/<имя репозитория>/` через `BASE_PATH` в workflow.
- Админка: **Sveltia CMS**. Она умеет одну file-коллекцию на `public/data/menu.json` со списками категорий и блюд и вход по personal access token без своего OAuth (кнопка токена есть, если не задан `base_url`). Своя админка поэтому не дублируется.
- Поле стоп-листа в CMS называется **«В наличии»** и пишет `available`. Выключено — стоп-лист. Подпись «Стоп-лист» на переключателе, который на самом деле означает «доступно», легко перепутать на демо.
- Четыре категории и двенадцать блюд: Антипасти, Паста, Гриль, Десерты. Стоп-лист: «Тальята». Не опубликовано: «Брускетта».
- Фото — с Unsplash, подписаны под реальные кадры. Видео — заглушки ffmpeg, чтобы ролик играл без чужого ролика не про то блюдо.
